Recreate the reference UI motion, a continuously moving horizontal carousel, as a single self-contained, responsive HTML file, as follows.

STRUCTURE

Create a horizontal carousel: a viewport (the scroller) that clips a track holding one row of placeholder cards.
- The cards sit side by side at a constant spacing: pitch ≈216 px (medium confidence), one card plus the gap to the next.
- Repeat the cards once (two identical copies back to back) so the track can wrap seamlessly; one copy must be at least as wide as the scroller.
- Each card contains: text.
- The motion runs along the horizontal axis only.

APPEARANCE (measured, approximate)

- Recorded viewport: 1280×800 px; page background #FAFAFA.
- Scroller: ≈760×200 px (medium confidence), top-left corner at x 260, y 300 of the recorded viewport (horizontally and vertically centred); background #F1F1F4 (medium confidence).
- Cards: ≈200×160 px each, vertically centred in the scroller; gap ≈16 px (medium confidence); background #FFFFFF (medium confidence); corner radius possibly ≈12 px (low confidence).
- Card text: colour #1A1A1A (medium confidence); font size possibly ≈16 px (low confidence); placed in the lower part of the card.
Match these sizes, colours and positions at the recorded viewport size; all content stays placeholder.

BEHAVIOUR

1. Autoplay: the track moves continuously to the right at ≈39 px/s with constant (linear) velocity and loops seamlessly by wrapping after one copy of the cards (the loop length was not visible in the recording).
2. Pause: when the pointer hovers or presses the scroller (the trigger was not visible in the recording; implement it as hover with a mouse, and pressing starts a drag anyway), autoplay slows to a stop over possibly ≈700 ms using a linear curve (low confidence); in the recording the slowdown was cut short by the next interaction, so its full length is extrapolated. It stays paused while the pointer stays over it.
3. Dragging: the content follows the pointer exactly along the horizontal axis (assumed: the pointer was not visible in the recording to compare); grabbing the track takes over from autoplay immediately. Use Pointer Events with setPointerCapture on the scroller; set touch-action: pan-y on the scroller so vertical page scrolling still works on touch; prevent text and image selection while dragging, and suppress the click on a card when the pointer moved. Drags in the recording reached ≈1720 px/s (medium confidence; 4 drags recorded).
4. Release (momentum): on release, keep moving with the pointer's release velocity and let it decay exponentially towards zero with τ ≈200 ms: v = v · e^(−dt/τ) each frame, using the real frame time so it is frame-rate independent, until it comes to rest. Measured release speeds were ≈750–1400 px/s; compute the release velocity from the most recent pointer movement (about the last half of τ), do not hardcode it. Pressing again while it is still coasting stops it at once and starts a new drag.
5. Abrupt stops: some drags ended abruptly without coasting, and no alignment to the cards was found. This may be a snap or the pointer stopping before release (they look the same without a visible cursor); do not add snapping unless intended.
6. Resume: once the motion has come to rest and the pointer has left, wait ≈100 ms (medium confidence; possibly ≈250 ms after release, low confidence), then autoplay resumes in its original direction, ramping up from standstill to ≈39 px/s over ≈750 ms using an ease-in-out curve (medium confidence).

OUTPUT

Build this as one self-contained, responsive HTML file named index.html: the markup, one <style> block and one inline <script> (the motion needs it). No frameworks, CDNs, external fonts, external images or build step; the file must work when opened directly in a browser.

- Content: build only the structure above, with neutral placeholders instead of real images or copy: images as a solid or gradient block with a fixed aspect-ratio, text as short role-named or lorem-style text (for example "Title", "Description"), icons as a simple inline SVG. Do not add UI beyond what is needed to demonstrate the motion.
- Layout: mobile-first and fluid, working from 320px wide phones to wide desktops, with the standard responsive <meta name="viewport"> tag. At the recorded viewport size keep the measured sizes, colours and the scroller's position from APPEARANCE (place its top-left corner exactly there, e.g. with the page's padding or margins; do not centre it unless APPEARANCE says it is centred); below that width the scroller may span the full width while the cards keep their measured size. Keep every motion value above as specified in CSS px, px/s and ms: they are measured design values, so do not scale them with the viewport.
- Motion: drive the track from one requestAnimationFrame loop that owns a single position value (autoplay, dragging, and momentum all change that one value). Advance it with the real frame time (dt) so speeds do not depend on the frame rate, apply it with the translate property, and wrap it modulo the size of one copy of the cards so the track never runs out of content. Velocity ramps (slowdown and resume) interpolate the velocity with the easing curves given above.
- Pointer: pointerdown / pointermove / pointerup / pointercancel with setPointerCapture; touch-action: pan-y on the scroller; user-select: none, and draggable="false" on placeholder images; cursor: grab, and grabbing while dragging.
- Hover: react to pointerenter / pointerleave from mouse pointers only (pointerType "mouse"), so a touch does not leave the scroller paused.
- Focus and visibility: make the scroller keyboard-focusable with an aria-label and pause autoplay only while it has keyboard focus (:focus-visible), not after a pointer press or drag; pause while the tab is hidden (visibilitychange) and reset the frame clock when it becomes visible so the track does not jump.
- Reduced motion: under prefers-reduced-motion: reduce, do not autoplay at all (the track starts and stays still); dragging and the release momentum still work because the user drives them.
- Semantics: use semantic elements (a section with an aria-label for the scroller, a list or articles for the cards, headings, p) and mark decorative placeholders with aria-hidden="true".

Fast drags could not be tracked precisely; treat peak and release speeds as rough.
